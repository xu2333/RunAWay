# Interleaved scope binding and late-revision stress

**Prepared and checked offline; no model measurement or service authority.**
The [preceding comparison](../source-accounted-encoding-v1/RESULTS.md) retained
30/30 in both methods. Its seven old losses did not recur, so it did not establish
an extra accuracy benefit. This protocol keeps both encoders unchanged and
changes the situations and compression pressure instead of declaring the tie a fix.

## What is harder by construction

Two new fictional people each have48messages interleaving four projects:
reading cards, activity instructions, a research memo and a small tool's guide.
All projects offer the same two complete actions, `先发简版` / `先发全版`, under
the same contextual predicates. The source explicitly gives each project's own
choices; common sense or a global personality label cannot identify the project.

Four preferences must survive together:

1. A project's original label and later corrected label refer to the same scope.
   The second person's rename permutation differs. Neither a new label nor its
   source episode's position licenses another project's preference.
2. A late same-context revision changes only the narrow exception. Its original
   global prerequisite remains; ordinary choices and other projects do not change.
   The late choice uses a source-defined opaque nickname (`青扣` / `白扣`), so
   full action identity must survive, not just an unexplained shorthand.
3. Assistant suggestions, quoted foreign-user text and mock tool completion
   claims are not new user preferences or confirmed real execution facts.
4. Missing prerequisites and genuinely conflicting possible contexts remain U;
   they must not be filled with generic cautious advice.

The current choices, older names, renamed scopes and late confirmations are
spread through the source rather than bundled in one final self-contained rule.
Every turn still names its own project; the intended reference does not depend
on guessing an ambiguous pronoun. The author knew past failures. Sources and
references were authored together, with a separate literal hand table checking
the constructor; this is not independently accepted semantic gold or a holdout.

## Locate loss before changing the method

For a valid failed card, use the frozen source links to compare source, raw graph
and public prompt: did the graph omit an alias/action link, miss the latest local
revision, erase a prerequisite, or promote an unconfirmed fact? If the graph kept
the content but rendering dropped it, that is a compiler issue. If the complete
card retains it and identical reads disagree, preserve reader variation rather
than asserting erased information. All these diagnoses remain source-linked
hypotheses until supported; no per-case labels or feedback enter this round.

Any targeted repair must be a separately versioned candidate after this frozen
round, with new scoped validation. Do not change inputs, references, budgets or
cards after observing failures. Both encoders and installed defaults stay intact.
New execution requires a direct finite51grant and successful three-platform CI
at the exact published implementation head. All previous scopes remain closed.
