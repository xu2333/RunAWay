# Fresh-person alias generalization

Prepared protocol; **no model measurements or service authorization**. This tests
whether the existing scope-alias repair transfers beyond its two consumed people.
Neither encoder, compiler nor standard reader changes; the application default
also stays unchanged. The previous comparison's 64/64 is not a result here.

Four newly authored fictional people (`otter`, `marten`, `tansy`, `sedge`) each have
48 phase-interleaved messages: 36 user messages and four each from assistant,
external context and tool. New domains concern research reproduction, community
help, travel planning and reading discussion. Shared action options prevent an
option's wording from revealing which project a name denotes. These are new
source texts and identities, but their author knows prior failures: this is an
adversarial development set, not an independent holdout or human-fidelity study.

## What can disappear

- **Two-hop identity:** original → intermediate → current name, with shuffled
  mappings and no single user quotation containing both original and current.
- **Namespace:** two independent projects share a bare name but choose opposite
  strategies. An absent namespace must not silently select a project.
- **Denied identity:** a lookalike name is explicitly a different project with no
  recorded choice. Foreign quoted examples are not the user's identity evidence.
- **Revision scope:** a late choice replaces only the narrow, higher-priority
  branch, inheriting its full conditions and simulation prerequisite.
- **Uncertainty boundaries:** missing permission, divergent possible projects or
  branches, and a sandbox's apparent execution remain unknown. Conversely,
  uncertain paired contexts that all imply the same action require that action.

The existing typed-alias contract demands a same-user-message literal witness for
both names and a canonical name present in the object. Naively connecting a
terminal name directly to the original fails that guard. A multi-name public
object can structurally retain intermediate edges; that does not prove compliance
with semantic guidance or predict model output. Negative co-quotation also does
not prove identity. Tests document these limits without weakening the contract
or modifying the method against this new test before measurement.

## Frozen design

| Axis | Planned value |
| --- | --- |
| Methods | source-accounted graph / existing scope-alias encoder |
| Whole public-card budget | 1536 characters, header and guide included |
| Draws | two independent extractions per person and method |
| Reading | two independent reads per card, both option orders per read |
| Primary denominator | 176 unique person/cases per method: 112 known, 64 unknown |
| Separate families | chain / qualified: 88 cases each |
| Public question forms | 176 unique forms total; own family bank has 88 |
| Controls | two bank-specific no-memory, then four own full-history |
| Attempt ceiling | 54: 6 controls +16 extractions +32 reads |

Each joint case requires all eight answers correct. Also report each generation,
person, family, eleven 16-case cohorts, 48 direct positive-name cases and 128
remaining cases. The latter includes mixed alias/context questions; it is not an
independent non-alias sample. Denied-identity and same-choice uncertainty each
have 16 cases. Reusing cases across methods does not produce 352 independent
observations; four fictional people cannot establish population stability.

All full-history controls must attain own44/44 across both orders, with no missing
answers and gain on personal known choices over the matching bank's no-memory
control, before any extraction. A failed control is not compression loss.
An invalid parent skips only its own two reads; all44of its cases remain missing
in the176denominator. Fatal transport/schema/decode/usage/runtime/guard failures
close the remainder. No retry, repair, resume or replacement; child timeout180s.
The ceiling limits attempts, **not aggregate tokens or money**.

Extraction sees only its own source, budget and unchanged instructions/schema;
no questions, reference, author table, evidence annotations, other draws, old
cards, responses or scores. Reading sees only the own complete public card and
own question bank; no private accounting or external name decoder. No real-person
data is involved. Follow any measured failure through the original source,
raw graph, public names/conditions and answers, separating omitted content,
wrong identity merge, stale choice, invalid product and read/order disagreement.
Do not repair original observations or shrink denominators.

## Reproduce preparation offline

```sh
python3 -B -m unittest discover -s tests -p 'test_fresh_alias_*.py' -v
python3 -B benchmarks/fresh-alias-generalization-v1/plan.py --out /tmp/fresh-alias-plan
```

The output directory must be new. `plan.verify` reconstructs exact requests and
checks source dependencies and all frozen hashes. Preparation has no model
transport. Its manifest and `approved=false` are not permission to execute.
A new direct finite grant and all three successful CI jobs on the exact published
implementation are required; old experiment budgets cannot be reused.

Fourteen offline tests cover sources, own-bank controls, eight-answer strict
scoring, invalid-parent missingness, fatal stops, no-reader supplements, input
integrity and standalone preparation. Reference-aware protocol oracles do not
measure card fidelity. The manually authored constructor table is an additional
consistency check, not independent semantic adjudication. Ten intentional damage
