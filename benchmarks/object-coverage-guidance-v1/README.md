# Source coverage guidance: unmeasured candidate

The [fixed-card read study](../fixed-card-fidelity-v1/README.md) finds six known
registration-grouping choices answered `U` in both reads/orders. The baseline
card named two objects in its raw table but supplied one decision node. This
candidate adds general source-only completeness guidance before the original
extraction request. It is a development hypothesis, **not a measured repair**.

The guidance asks the producer to review every independently supported scope,
retain its known decisions/conditions, and avoid substituting object names or
taglines for decisions. It explicitly disallows pretending coverage improved
by deleting object entries, repeating nodes or inventing choices for unknown
domains. No question, reference, old card, response, score, object label or
case-specific correction is appended.

Wire version/schema, binder, compiler, fixed header/guide and whole1536-character
budget remain source-order-v3. Only a generic prefix changes. The production
default is unchanged and this module prepares requests without invoking a model.
Source completeness and semantic support are not mechanically proved by these
instructions. Behavioral source-backed endpoints remain necessary: the
[metadata-only counterexample](../fixed-card-fidelity-v1/incidence-invariance.synthetic.json)
clears the incidence warning while preserving every public memory byte.

No model call has tested this candidate. Fresh baseline/candidate generation,
repeated reads, unknown-preservation controls, invalid-product denominators and
explicit new service authorization are needed before drawing a performance
conclusion. Development on a known failure does not create an independent
holdout or establish generation stability.
