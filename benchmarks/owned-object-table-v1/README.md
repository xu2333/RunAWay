# Object-table wire candidate — measured capacity and budget failure

The [closed h93probe](../object-table-probe-v1/MEASURED.md) produces two legal
12-object tables but no valid1536card: packed attempts are1999/2170characters.
The candidate's40cases remain missing. The original wire and calibration below
are preserved; object-count alignment does not establish usable compression.

The owned-condition experiment's two h93 extractions each contain **24 rows
across 14 distinct objects**. The private flat-row schema allows up to30 rows,
but the public grouped representation allows only12groups. Both products are
therefore invalid before any character-budget judgment. Their original outputs,
failed bindings, skipped readers and missing cases remain in the measured
record. This candidate does not repair, replace or reread them.

The candidate makes object capacity explicit in the wire schema: an at-most 12
entry private object table and at-most 30 total rows. Each row refers to a defined
object index and still owns all its necessary conditions. Indices are expanded
to full natural-language names before the unchanged owned-condition compiler,
renderer and codec run. The public card has no object-index decoder or external
dictionary, and expanded names count toward the same whole-card budget.

Object names are unique literal labels; they do not carry shared prerequisites.
Decision questions remain per-row, so grouping plan choice and execution
permission under one object does not make their conditions or actions compete.
The encoder sees only its own source, without a serialized character budget,
questions, old model responses, references or feedback.

Six offline tests cover source isolation, exact expansion/binding parity,
12 used objects, rejection of 13 objects/31 rows, undefined/Boolean indices,
duplicate names, empty decisions, retained unknowns and hard budget failure.
They are code calibration, **not successful model generations**. Object naming,
grouping and condition annotation can still be wrong or incomplete. Text-field
length, other binder constraints and the whole-character budget can still fail.
The new wire prevents this particular group-count mismatch for a valid object
table; it is not a proof of full schema alignment or semantic fidelity.

```sh
python -m unittest discover -s tests -p test_owned_object_table.py -v
```

No model calls, current-scope request changes, new service authority or product
default changes are included. A future model test needs a separately frozen
finite scope and new approval.
