# Source-only model-generated order annotations — unmeasured candidate

The [fixed-view diagnostic](../order-target-read-v1/MEASURED.md) reaches23/23
after a developer supplies the method/execution binding. This candidate makes
that annotation part of the encoder's JSON output. No developer-selected row,
source-case mapping,old card,question or reference enters extraction.

Each original graph node gains`order_split`,normally null. For a current choice
whose complete ordered action is exactly`先`+a separately source-offered method
name,the encoder may provide the core label,its source quote,and an independent
execution-target name. Status nodes cannot be split. The existing graph compiler
first resolves active choices and preserves other facts;only active annotations
become bindings. Superseded representation annotations are not silently copied
onto a new action. The full original ordered phrase and guards survive on the
new target through the explicit scope-preserving projection.

No binding is filled in when the encoder returns null. At most4active splits,
the original30active-row/12object limits and1536whole-character cap remain.
This supports only the narrow leading-order operator,not a general semantic
parser. Source quotes,prefix equality and structure do not prove that a supplied
method label is an independently offered option or that the decomposition is
semantically right. Model assignment remains unverified. Original ordering that
belongs to a choice name must not be stripped globally.

The deterministic damage helper removes only execution targets generated from
these annotations. Core choice rows and all guards are preserved. Missing splits
or exact ordered wording remaining elsewhere make damage ineligible;there is
no repair or extra generation. Literal absence is not proof that no paraphrase
or implication retains the information. Damage results must be interpreted with
that limitation and do not change any source-preference gold label.

Eight offline tests cover source-only payloads,no manual row input,binding/guard
conservation,user roles,status rejection,backward revision/past facts,null without
auto-fill,narrow erasure,contamination and inactive-annotation quotes. These are code invariants,not model
observations. The [proposed22-call probe](../source-order-probe-v1/README.md)
requires new authorization. No production-default change or independent
semantic acceptance follows from this implementation.
